# 声画织场可重复性技术评估：分析身份、冻结交付与工具升级

评估对象：当前基线代码（HEAD `d1111ac`）。评估方式：静态代码追踪 + 用实际生成的音频/视频做的有界实验（E1–E9）。所有实验媒体均由 FFmpeg 合成（2–20 秒、≤320×180），每个实验使用独立数据目录，证据 JSON 存于 `docs/assessment-evidence/`。本评估不提交任何功能实现，只给出结论与建议。

实验环境：Python 3.11.2（aarch64）、PyAV 16.1.0（自带 FFmpeg 8.0 系动态库：libavformat 62.3.100）、imageio-ffmpeg 提供的 FFmpeg 7.0.2 静态二进制（基线默认）、另取 FFmpeg 4.2.2 静态二进制做版本对照。注意：本机验收环境（README 声明 macOS ARM64 + Python 3.14）与本评估环境不同，但全部结论基于代码路径与在本环境实际观测到的行为，不涉及平台特有假设。

## 1. 同一份媒体字节如何形成分析身份、剪辑身份与印本引用

### 1.1 字节 → 内容身份（blob）

上传字节先落临时盘、经 PyAV 探测（`reel_loom/probe.py:7`），再按 **SHA-256 全文哈希** 进入内容寻址存储（`reel_loom/blobs.py:26-50`）。同一哈希只存一份；`resolve(verify=True)` 在每次被分析/渲染/打包读取时重新哈希校验（`blobs.py:52-62`）。**内容身份 = 原始字节的 SHA-256**，与文件名、标签、上传时间无关。

资产身份：相同字节的重复上传在 `ready` 状态下复用同一 `asset_id`（`reel_loom/assets.py:19-22`，E1 观测 `dedup_same_bytes_same_asset: true`）。探测元信息（流列表、时长、采样率等）在接收时刻由 **PyAV** 算出并随资产行冻结（`assets.py:24`），之后不再重探。

### 1.2 字节 → 分析身份

分析指纹在 `reel_loom/analysis.py:29`：

```
fingerprint = sha256_canonical({"blob": <blob哈希>, "kind": <signal|waveform|loudness>,
                                "settings": <归一化参数>, "algorithm": 1})
```

- 复用键只有四个维度：内容字节、分析种类、归一化参数、硬编码常量 `"algorithm": 1`。**不含 FFmpeg 版本、不含 PyAV 版本、不含流选择器、不含探测元信息，也不含资产 id**。
- `analyses.fingerprint` 有 UNIQUE 约束（`reel_loom/schema.py:50`），命中即整行复用（`analysis.py:30-33`、`51-61`）。E1 观测：同一请求重复提交返回同一 `analysis_id`；改 `threshold_db` 产生新身份。
- **分析身份锚在字节、不锚在资产行**（E9）：接收 → 分析 → 退役 → 重传同一批字节（因去重只匹配 `ready` 资产，产生新资产行）→ 对新资产再发同一分析请求，返回的是**资产字段仍指向已退役旧资产**的那一行分析；新资产自己的 `analyses` 列表为空。解释历史时要注意：分析行的 `asset` 字段记录的是"首次计算时所在的资产行"，不是"当前请求的资产行"。
- 三条分析链的工具依赖不同：
  - `signal`/`waveform`：CLI FFmpeg 解码（`-map 0:a:0 -ac 1 -ar 16000 pcm_s16le`，`reel_loom/processes.py:81-85`）→ 纯 Python 统计（`reel_loom/samples.py`，确定性）。
  - `loudness`：CLI FFmpeg `loudnorm` 滤镜 JSON 输出（`analysis.py:63-85`），同样 `-map 0:a:0`。
  - 即：**解码/测量委托给外部 CLI，统计与指纹在本进程内**。PCM 字节一旦变化，下游统计必然变化。

### 1.3 字节 → 剪辑与渲染身份

- 剪辑卷每个修订的文档（镜段、入出点、累计时间轴）整体哈希为 `reel_hash`（`reel_loom/reels.py:41-44`），历史修订只读。
- 渲染单入队时冻结快照：修订文档 + 版式规格 + **接收时刻冻结的源元信息**，`fingerprint = digest(snapshot)`，`schema: 1`（`reel_loom/planner.py:11-29`）。快照同样**不含任何工具版本**。
- 渲染用 CLI FFmpeg 滤镜图（trim/aresample/volume/concat/fps + libx264/AAC 或 pcm_s16le，`planner.py:31-68`），产物字节哈希入 blob，与票据成功状态同一事务提交（`reel_loom/artifacts.py:10-23`）。
- 成片验规（`reel_loom/conformance.py`）用 **PyAV** 全解码当前字节做检查——它验证的是"今天的解码器看这批字节"，不是"当初那台编码器"。

### 1.4 字节 → 印本引用

印本清单 = `{schema:1, ticket, fingerprint(票据), snapshot, files[](成片blob+size), caption}`，清单再哈希为印本指纹（`reel_loom/imprints.py:28-30`），ZIP 成员时间戳固定为 1980-01-01（确定性打包，`imprints.py:36-44`）。`imprints.fingerprint` UNIQUE（`schema.py:55`）。核验（`imprints.py:71-95`）只重读包内字节做 SHA-256 比对，**不依赖来源资产状态、不重新解码、不依赖任何工具版本**。血缘闭包（`reel_loom/lineage.py`）把 渲染单→修订→版式→源资产→blob→产物→印本 连成有向图，E7 观测节点/边类型齐全。

**身份链小结**：字节哈希是唯一的内容锚点；分析身份锚在"字节+参数+常量"；渲染身份锚在"冻结快照"；印本身份锚在"清单（含票据号）"。整条链上没有任何一环记录产生结果所用的解码器/编码器版本。

## 2. 现在结果可重复的范围（均为观测事实）

| 范围 | 观测 | 证据 |
| --- | --- | --- |
| 同字节重复上传 | 复用同一 asset | E1 |
| 同参数重复分析 | 同一 analysis_id；signal/loudness 各重复 3 次结果一致（waveform 与 signal 共用同一解码与统计路径） | E1、E2 |
| 同一冻结快照重复渲染（同机同工具） | MP4 与 WAV 产物**字节级相同**，blob 去重为同一哈希；跨全新数据目录也相同（E3 与 E5 的同一快照产出同一 blob `1b69cffe…`） | E2、E3、E5 |
| 印本核验 | 改剪辑、退役来源、切换 CLI 工具版本后，`verify` 仍全部通过 | E3、E6、E7 |
| 并发同一来源 | 8 并发相同分析 → 1 行 1 事件 1 id；4 并发相同印本 → 1 行；2 并发同快照渲染 → 共享同一 blob | E5 |
| 重混流（remux，相同基本流、不同容器字节） | 新 asset、新分析身份；本样本上 signal/loudness 数值与原件一致 | E1 |
| 退役后重传同一批字节 | 新资产行继承按字节键入的旧分析行；新资产自身分析列表为空 | E9 |

可重复的边界由此清楚：**"可重复"= 同一批字节 + 同一组冻结参数 + 同一个 CLI 二进制 + 同一个 PyAV 版本**。前两项由指纹显式锚定；后两项只由"部署没换"隐式保证。

## 3. 工具版本或流选择改变时，哪些结论不能沿用

### 3.1 观测到的差异（不是推测）

1. **缓存跨工具版本静默复用**（E3、E8）：同一数据目录把 `LOOM_FFMPEG` 从 7.0.2 换成 4.2.2 后，同样的分析请求返回**同一个 analysis_id、同一份旧结果**。指纹没有工具维度，系统无从察觉工具已变。
2. **分析解码路径确实存在版本敏感输入**（E3b/E3c）：5 种合成输入中有 4 种（44.1 kHz 正弦、48 kHz WAV 正弦、门控脉冲、15 kHz 高频）在 4.2.2 与 7.0.2 下解出的 16 kHz 单声道 PCM **字节不同**；44.1 kHz 样本 48000 个采样中 8807 个不同（最大差 1 LSB），落到存储结果上 `rms_dbfs` 第 4 位小数不同（-21.074 vs -21.0741）。差异很小，但**足以让"同一指纹"对应两份不同的存储内容**。
3. **渲染路径字节必然漂移**（E3）：同一冻结快照，4.2.2 与 7.0.2 渲染出的 MP4 **和 WAV** 字节都不同（WAV 只是 PCM，说明差异来自滤镜图/重采样实现，不只是编码器）。票据指纹相同、产物哈希不同——**指纹 ≠ 产物内容身份**，它只在同一工具代内与产物字节重合。
4. **流选择是隐式的"容器内第一条音频流"**（E4）：同一批基本流，仅交换容器内音频流顺序，loudness 从 -27.84 LUFS 变为 -38.25 LUFS（相差 10.4 LU），渲染 WAV 字节也随之改变。当前 API 没有流选择参数，无法请求第二条音频流的分析；指纹里也没有流维度。
5. **"工具版本"今天就不是单一值**：探测/验规走 PyAV 16.1（FFmpeg 8.0 系库），解码/渲染/响度走 CLI 7.0.2，`LOOM_FFMPEG` 只能切换后者（`reel_loom/config.py:22`）。一次"升级工具"有两个独立轴，而系统两处都不记录。

### 3.2 观测到的稳定（也不能外推为保证）

- loudnorm 数值（integrated LUFS、true peak dBTP、LRA、阈值）在 4.2.2 与 7.0.2 之间对本报告全部 6 个测试输入**逐位一致**（E3、E3b）。这只是对这组输入、这两个版本的观测；loudnorm/ebur128 的实现历史上变过，未来版本不保证。
- 同一工具代内渲染字节确定（E2）。跨代不成立（见 3.1-3）。

### 3.3 尚待验证的假设（明确标注）

- **H1**：PyAV 大版本升级可能改变探测结果（时长估计、流顺序、像素格式判定），从而改变新接收资产的冻结元信息；同一批字节在新 PyAV 下重新接收可能得到不同 metadata。未实测（本环境只有一个 PyAV）。
- **H2**：验规检查（时长容差 ±0.15 s、帧率有理数相等）在未来 PyAV 下可能对历史产物给出不同判定——验规是对"今天的解码器"的陈述。未实测。
- **H3**：`signal` 的静音区间对 1 LSB 级 PCM 漂移敏感：阈值恰好在边界附近的输入，版本切换可能增删静音段。E3c 所用样本静音区间一致，未构造出反例，但机制上成立。
- **H4**：loudnorm 在更宽动态/真实节目素材上可能出现版本间数值差异。本报告合成素材未观测到。

### 3.4 工具或流选择变化后不能沿用的结论

- 一切**数值型分析结论**（dBFS 峰值/RMS、静音区间、波形桶、LUFS 系列、dBTP）：只对"计算它们的那一代工具"有效；升级后旧值只能作为历史记录引用，不能当作"当前工具也会得到的结果"。
- **产物字节哈希**：换工具后同一快照会产出不同字节，旧哈希不能作为新渲染的期望值。
- **"第一条音频流"这个隐式约定**：容器重打包（不改变任何基本流）即可改变分析与渲染对象；凡涉及多音频流来源的历史结论，必须连同"当时的流顺序"一起理解。
- 可以沿用的：**字节身份**（blob 哈希）、**印本核验结论**（字节级，与工具无关）、**修订/版式/快照的结构哈希**（纯 JSON 序列化，不依赖媒体工具）。

## 4. 两条路线比较：保留旧计算环境 vs 重算历史结果

### 路线 A：保留旧计算环境

做法：按时代保存 CLI 二进制（`LOOM_FFMPEG` 已支持指定）与 PyAV 版本，需要解释历史时用对应时代的环境启动服务。

- 优点：与现有缓存语义自洽——旧分析本来就是旧工具算的，旧环境能**原样重述**；E2 证明同一工具代内渲染字节确定，旧交付在旧环境下可逐字节重建；印本核验天然与工具无关。
- 缺口（代码现状）：**系统不记录任何工具身份**——分析行、票据快照、产物元信息、印本清单里都没有版本字段。保留环境而不记录"哪条结果属于哪个环境"，解释工作仍靠人肉档案。PyAV 轴无法按请求切换，只能整服务回退。旧二进制有安全与维护成本。

### 路线 B：重算历史结果

做法：升级工具后让历史分析/渲染在新工具下重算。

- 分析：输入（blob）与参数都在，技术上可重算。但指纹没有工具维度，**当前代码里"重算"只能体现为删除 `analyses` 行后重跑**——旧值随之灭失，任何引用过旧值的交付文档（如"该素材 RMS 为 -21.074 dBFS"）将永远无法从系统复现原句。E3c/E8 证明重算结果可能不同（量级小但存储内容不同）。
- 渲染：重算必然是新票据、新产物字节（E3）。历史印本打包的是旧字节、按字节核验，**重算不会让旧印本失效，但也永远复刻不出印本里的字节**。系统会持有同一快照指纹的两代产物，且没有字段记录"为何存在两代"。
- 结论：**重算回答"现在会算什么"，保留回答"当时算的是什么"——两者不可互相替代**。对"历史分析和冻结交付仍能解释得清楚"这个目标，重算单独不构成方案。

### 建议的取向（评估意见，非实现）

分析侧走"**版本化身份**"：工具升级 = 新分析身份（给指纹增加工具维度或提升 `algorithm` 常量），旧分析行保留只读、永不原地替换；交付侧走"**字节冻结 + 环境记录**"：印本维持字节级核验不变，另把工具身份写入快照/清单的扩展位（`schema`/`algorithm` 常量就是现成的升级缝，`analysis.py:29`、`planner.py:25`、`imprints.py:28`）。旧计算环境至少保留到引用它的印本越过核验保留期。

## 5. 并发、退役与旧交付核验：矛盾如何处理

以下均有实验支撑，机制描述对应代码行。

1. **多个请求并发计算同一来源**：持久化是单飞的——指纹 UNIQUE + 写事务内复查（`analysis.py:52-56`），8 并发只得 1 行（E5）；但**计算本身不是单飞**，重复请求可能各自跑一遍 FFmpeg，后到者在写事务里发现已存在即丢弃。同一进程内这无害（结果必然相同）；真正的风险窗口是**跨重启换工具**：`LOOM_FFMPEG` 在进程启动时固定，运行期不会变，所以单进程内不存在"两个版本竞速"；但重启换装新工具后，旧工具算出的在途结果不会被特别标记——它与新工具的结果共用同一指纹，谁先入库谁生效（代码推断，未构造观测）。渲染侧同理：同快照两票据并发渲染，产物字节相同则 blob 去重（E5 观测共享 blob）。
2. **计算期间来源退役**：分析在落库前的写事务里复查 `ready`（`analysis.py:53`）——E6 观测到计算中途退役时分析以 `asset_retired` 失败、结果丢弃。结局由时序决定（退役的写事务先于分析落库则分析失败，反之分析正常入库），但两种结局都是完整状态，不存在"半截分析"；已冻结的渲染单不受退役影响，渲染器直接按快照解析 blob（`rendering.py:23`），E6 观测退役后冻结票据渲染成功；退役资产的 blob 仍被资产行引用，资源清扫不会回收（`resources.py:10`，E6 观测 `sweep_removed: []`），运行中的 FFmpeg 不会读到被删文件。即：**退役只撤销"新引用的资格"，不撤销"已冻结工作的读权"，也绝不物理删除**（`assets.py:47-53`）。新分析、新剪辑卷、新票据引用退役来源均被拒（E6 全部观测为 `asset_retired`）。退役后重传同一批字节会产生新资产行，但分析按字节键入，新资产直接继承旧分析行（E9）——"退役再重传"不会触发重算，也不会清空历史分析。
3. **旧交付仍需核验**：印本核验只读包内字节（`imprints.py:71-95`），E3/E6 观测其在工具切换、来源退役、剪辑卷改稿后全部有效。三者不冲突的根本原因是：**核验的语义是"这批字节是否还是那批字节"，而不是"今天的工具是否还会产出这批字节"**。需要警惕的是把验规（conformance）误当历史核验用——验规用当前 PyAV 全解码，语义是"现在能否解通"，属于 H2 假设区。

## 6. 暴露错误复用的对照依据

核心对照（E8，端到端、在系统内观测）：

1. 选 44.1 kHz 正弦 WAV——已证其 16 kHz 解码在 7.0.2 与 4.2.2 间不同（E3b/E3c）；
2. 7.0.2 下 `POST signal`：得 `analysis_d7ac…`，`rms_dbfs = -21.074`；
3. 同一数据目录换 4.2.2 重启，同一请求返回**同一 id、同一 -21.074**（缓存）；
4. 用 4.2.2 独立重算同一请求：`-21.0741`。**系统当前应答 ≠ 当前工具的真实计算**（`cached_matches_fresh_ff4: false`）。

这套对照的构造方法可推广为升级验收测试：先差分探测找出版本敏感输入（E3b 的方法：同一输入在两个二进制下比 PCM 哈希与 loudnorm JSON），再用敏感输入做"换工具后缓存应答 vs 现场重算"的比对。凡差分为空集的输入类，可声明在该版本对之间复用安全；凡非空，就必须走新身份。

辅助对照：同一冻结快照在 4.2.2/7.0.2 下渲染字节不同（E3，`video_bytes_differ`/`wav_bytes_differ` 均 true）——证明"指纹相同 ⇒ 字节相同"跨工具代不成立；同一批基本流换容器顺序后 loudness 差 10.4 LU（E4）——证明"内容相同 ⇒ 分析相同"对流选择不成立。

## 7. 建议的兼容承诺（供制作团队决策，未实现）

1. **工具身份成为一等数据**：分析、票据快照、产物元信息、印本清单记录 CLI FFmpeg 版本串与 PyAV/FFmpeg 库版本。这是其他一切承诺的前提；当前代码一处都没有。
2. **升级即新身份，旧结果只读**：工具版本变化时提升 `algorithm`/`schema` 常量或扩展指纹维度；旧分析行、旧产物、旧印本永不删除、永不原地改写。重算只能"新增一代"，不能"替换历史"。
